# Blender MCP — does it work, and is Blender worth using for SeedVales?

Date: 2026-10-01 · Type: quick research (≈30 min) · Status: informational → plan [`render--004`](../plans/render--004--asset-pipeline-and-audit.md) (audit + guard test first, optimisation only with a measured trigger; D-REN-8)

## TL;DR

- **Blender MCP works** in this environment: Blender 5.2.0 LTS, addon 1.8, protocol 13 (up to date), telemetry off. A live round-trip passed: import `public/assets/village.glb` → Python stats → viewport screenshot → cleanup.
- **Blender is worth it as an offline asset-pipeline tool**, not as a content source for the runtime. The game must stay procedural + glTF loaded by Three.js; Blender only prepares/optimizes `.glb` files that land in `public/assets/`.
- Highest value, lowest cost: **(1) asset audit and optimization** (tri counts, materials, atlases), **(2) authoring missing animal models** (rat, hare, boar are procedural placeholders today), **(3) medieval props/buildings** missing from the Quaternius packs. AI generators (Rodin/Hunyuan/Tripo) are disabled and **not recommended** (they clash with the art style and license/provenance is unclear).

## 1. Does Blender MCP work?

Checked on 2026-10-01 from Claude Code:

| Check | Result |
|---|---|
| `get_addon_status` | `up_to_date: true`, protocol 13/13, addon 1.8, Blender **5.2.0 LTS**, `premium_generators: []`, telemetry `false` |
| `get_scene_info` | OK (default scene: Light, Camera) |
| `execute_blender_code` (glTF import + analysis) | OK — `village.glb` imported in 0.17 s |
| `get_viewport_screenshot` | OK |
| Poly Pizza integration | **disabled** (needs a free API key in the addon's N-panel) |
| Poly Haven / Sketchfab / Hyper3D / Hunyuan / Tripo | not checked/enabled; generators need paid keys |

Example of what the tool returned for `village.glb` (Quaternius Medieval Village): 46 objects, 23 meshes, **25 221 tris**, 8 materials, 8 textures. Heaviest parts: `Roof_RoundTiles_8x10` (4 480 faces), `Roof_RoundTiles_8x8` (3 888), `Corner_Exterior_Brick` (3 102), `Prop_Wagon` (1 672). The roof tiles are the most expensive part of the pack. That's a real optimization target, since `structures.ts` merges these templates per material and instances them per settlement.

Known caveats:
- `execute_blender_code` runs arbitrary Python in the user's Blender. Fine locally, but every script should leave the scene clean (this check removed what it imported).
- Blender must be running with "Start MCP Server" enabled in the addon panel; otherwise every tool fails. It is a **developer-only** dependency and must never become part of `pnpm build`, CI or e2e.
- Non-English Blender UI: look nodes up by `type`, not name (MCP server instruction).
- Community reports say the first command after connecting sometimes fails and a retry fixes it. We didn't hit that here.

## 2. Is Blender worth it for SeedVales, and for what?

Context: art direction is decided (`docs/design/rendering-camera-and-art.md`). Terrain and most buildings are procedural low-poly; characters and animals are imported glTF. Current assets in `public/assets/` total about 18 `.glb` files (≈17 MB): 8 animals, 4 character bodies plus heads plus `anims.glb`, and `nature.glb`, `village.glb`, `props.glb`. The render code already falls back to procedural geometry when a model is missing (`actors.ts`, `structures.ts`, `vegetation.ts`, `carts.ts`).

### Recommended uses (in priority order)

1. **Asset audit + optimization (high value, low cost).** Scripted via MCP: per-asset tri/material/texture report, decimate the heavy roof tiles, merge materials into one atlas (fewer draw calls after `mergeTemplate`), strip unused nodes/animations, re-export glTF. Feeds the render wave (`render--002/001/003`) and the perf budget. Before/after must be checked with `pnpm bench:render` (JS phases only; SwiftShader caveat). Pair with `gltf-transform` (CLI) for Draco/Meshopt and texture compression. That part needs no Blender.
2. **Missing animals (medium cost).** Rat, hare and boar are procedural placeholders. Options: Poly Pizza (CC0/CC-BY low-poly, style-compatible with Quaternius; needs API key + creator credit for CC-BY) or hand-modelling plus re-using the Quaternius rig/animation naming so `actors.ts` loads them like the existing animals.
3. **Medieval props and building pieces (medium).** Items from VISION-APPENDIX (waterskins, campfires, torches, carts, market stalls, wells) can be modelled low-poly in Blender with the same palette/texture atlas as the Quaternius packs, then exported as named nodes into `props.glb`, so the existing `getObjectByName` lookup keeps working.
4. **Look-dev / reference renders (low priority).** Lighting and colour-grading mood boards (Poly Haven HDRIs) to pick target looks for the render wave. Useful but optional.
5. **Calibration helpers (optional).** Bake a heightmap or a world chunk from the seeded generator into Blender for visual inspection. This overlaps with `tools--001--calibration-lab` and is probably cheaper in-browser.

### Not recommended

- **AI 3D generators (Rodin, Hunyuan3D, Tripo):** inconsistent topology and style next to Quaternius low-poly, unclear licensing, paid keys. Revisit only for one-off hero props.
- **Sketchfab realistic models:** wrong style (no-fantasy medieval *low-poly*), heavy, mixed licenses.
- **Moving procedural content (terrain, settlements, buildings) to Blender:** this would break deterministic seed generation and the world cache (`GEN_VERSION`). The world must stay generated in code.
- **Blender as a runtime/build dependency:** the asset pipeline output (`.glb`) is committed; Blender stays a manual/dev tool.

## 3. Practical workflow if adopted

1. Commit source `.blend` files outside `public/` (e.g. `assets-src/`, possibly via Git LFS) and keep exported `.glb` in `public/assets/`.
2. Keep node names stable. The render code looks parts up by name (`getObjectByName`), so a renamed node silently falls back to procedural geometry.
3. Post-process each export with `gltf-transform` (dedupe, prune, Meshopt/Draco, KTX2/WebP), then run `pnpm bench:render` and `node scripts/e2e/tour.mjs` for a visual check.
4. Licensing: record source and license per asset (Quaternius CC0; Poly Pizza CC-BY needs credit) in a credits file.
